# LingBot-VA 基于 TPDM 式跳步与 Hazard 停止控制的统一训练方案

## 一、研究目标与总体思路

### 1.1 核心目标

目标不是寻找某一个固定的最优停止时间，而是学习一个统一的调度策略，使其在不同状态下都能自适应决定：
- 当前视频去噪是否应该停止
- 若不停止，下一步应当跳多远

这样得到的不是单点阈值，而是一条完整的视频去噪路径。

### 1.2 训练主线

本方案只保留一条训练主线：
1. 策略网络在每一步输出跳步分布与 hazard 增量
2. 系统按照当前策略采样整条视频去噪路径
3. 动作分支在该路径诱导的视频表征上生成机器人动作
4. 根据动作质量与计算代价计算整条路径的回报
5. 用 PPO 直接优化这条路径的采样概率

### 1.3 Hazard 建模的核心原因

采用 Hazard（风险函数）建模停止决策的原因：
- **理论基础扎实**：来自生存分析，概率语义严格
- **数值稳定**：条件停止概率直接由增量计算，无需除法
- **单调累积**：Hazard 单调递增，显式避免停止信号抖动
- **初始值自然**：F_0 = 0 天然成立，不需要人为设定

## 二、模型定义：统一的跳步与 Hazard 停止控制策略

### 2.1 状态定义

在一个 autoregressive chunk 内，设第 k 个视频去噪步的策略状态为：

```
z_k = (h_k, t_k, c_k)
```

其中：
- h_k：当前视频分支的 hidden feature
- t_k：当前 flow time
- c_k：辅助条件（已用预算、任务条件、可选的 phase 信息）

### 2.2 策略输出

策略网络在每一步输出三项：

```
(alpha_k, beta_k, ΔH_k)
```

其中：
- (alpha_k, beta_k)：用于定义 Beta 分布，在"继续"的前提下采样跳步比例 r_k
- ΔH_k：当前步的 hazard 增量（非负）

### 2.3 Hazard 增量的计算

为了保证 hazard 单调累积，将增量约束为非负量：

```
ΔH_k = softplus(g(z_k))
```

其中 g(·) 是轻量 hazard 头（神经网络）。

### 2.4 累积 Hazard 与停止概率

**累积 Hazard：**
```
H_k = H_(k-1) + ΔH_k
```

初始值：H_0 = 0

**累积停止趋势（CDF）：**
```
F_k = 1 - exp(-H_k)
```

这里 F_k ∈ (0, 1) 可以理解为"到第 k 步为止，模型认为已经足够接近停止条件的程度"。

**条件停止概率：**
```
h_k = 1 - exp(-ΔH_k)
```

这是"在前面都没有停的条件下，于第 k 步停止"的条件概率。

**关键优势：h_k 直接由当前增量 ΔH_k 计算得到，不需要差分或除法！**

## 三、单步决策、训练期探索与部署期停止接口

### 3.1 训练期采样

在第 k 步，策略首先根据 hazard 增量构造该步的条件停机概率：

```
h_k = 1 - exp(-ΔH_k)
```

训练期采用概率采样：

```
b_k ~ Bernoulli(h_k)
```

**如果 b_k = stop：**
- 视频去噪立即结束
- 当前视频表征写入缓存并进入动作分支

**如果 b_k = continue：**
- 从 Beta 分布中采样跳步比例：
  ```
  r_k ~ Beta(alpha_k, beta_k)
  ```

### 3.2 时间更新

为保证 time 单调推进，对剩余未去噪量进行更新。设 ρ_k = 1 - t_k，则：

```
ρ_(k+1) = r_k × ρ_k
t_(k+1) = 1 - r_k × (1 - t_k)
```

这样，r_k 只控制"继续时向前推进的幅度"，不会与停止逻辑混淆。

### 3.3 完整路径

经过若干步之后，可得到一条完整的视频调度路径：

```
τ = ((b_1, r_1), (b_2, r_2), ..., (b_T, r_T))
```

其中，一旦某一步出现 stop，路径即终止，后续不再继续进行视频去噪。

**训练期采用 Bernoulli 采样，是为了保留探索能力**；否则模型会过早退化为固定停法，难以比较"当前就停"和"继续几步后再停"哪一种最终 reward 更高。

### 3.4 部署期停止接口

部署阶段不再对 stop 进行随机采样，而是将累计停止趋势转换为布尔信号。

**推荐的部署规则：**

```python
stop_now = True  if k >= K_max
stop_now = True  if k >= K_min and F_k >= η
stop_now = False otherwise
```

其中：
- K_min：最小允许停止步数（避免过早停止）
- K_max：最大步数（避免无限循环）
- η：累积趋势阈值（如 0.85）
- F_k = 1 - exp(-H_k)：累积停止趋势

这一规则给视频预测 loop 提供了明确的 stop_now 接口，同时使阈值只服务于部署，不干扰训练阶段的策略探索。

**可选增强：**

若验证阶段发现阈值附近存在轻微抖动，可选地加入"双步确认"规则，即要求 F_(k-1) 与 F_k 连续两步超过阈值后才停止；但该项应作为部署级增强，而不应破坏训练主线。

## 四、奖励函数与优化目标

### 4.1 路径级奖励

在该统一方案中，不再把单个 stop time 作为最终学习目标，而是直接评价整条路径 τ 的总体价值。设初始状态为 x，则整条路径的奖励定义为：

```
R(x, τ) = U(x, τ) - λ × Cost(τ)
```

其中：
- U(x, τ)：按照路径 τ 完成视频去噪后，再由动作分支生成机器人动作所获得的动作效用
- Cost(τ)：该路径带来的计算代价
- λ：权衡系数，用于控制"效果优先"与"效率优先"的相对程度

### 4.2 动作效用（第一版）

为了尽快落地，第一版动作效用建议采用离线动作误差形式：

```
U(x, τ) = -L_act(â(x, τ), a*)
```

其中：
- â(x, τ)：在路径 τ 诱导的视频表征上生成的动作
- a*：数据中的标注动作
- L_act：动作损失函数（如 MSE）

### 4.3 计算代价

计算代价建议先采用视频去噪步数或对应的前向次数：

```
Cost(τ) = 视频去噪步数
```

因为这与现有代码实现最一致。

## 五、PPO 在该模型中的作用

### 5.1 优化目标

PPO 在这里优化的不是某个单独的 stop time，而是整条路径 τ 的采样概率。也就是说，PPO 的目标是让高奖励路径在未来更容易被采样到，让低奖励路径更少出现。

### 5.2 路径概率

整条路径的策略概率可写为：

```
π_θ(τ|x) = ∏_k π_θ(b_k | z_k) × ∏_(k:b_k=continue) π_θ(r_k | z_k)
```

其中：
- π_θ(b_k | z_k)：来自 Bernoulli 分布，概率为 h_k = 1 - exp(-ΔH_k)
- π_θ(r_k | z_k)：来自 Beta 分布密度

### 5.3 路径对数概率（用于梯度计算）

假设路径在第 τ 步停止，则：

```
log π_θ(路径) = log h_τ + ∑_(k=1 to τ-1) log(1 - h_k) + ∑_(k=1 to τ-1) log Beta(r_k | alpha_k, beta_k)
```

**代入 h_k = 1 - exp(-ΔH_k)：**

```
log(1 - h_k) = log(exp(-ΔH_k)) = -ΔH_k
```

因此：

```
log π_θ(路径) = log(1 - exp(-ΔH_τ)) - H_(τ-1) + ∑_(k=1 to τ-1) log Beta(r_k | alpha_k, beta_k)
```

其中 H_(τ-1) = ∑_(k=1 to τ-1) ΔH_k

**计算非常简洁，适合 PPO！**

### 5.4 PPO 更新

PPO 根据当前策略采样得到一批完整路径，计算每条路径的奖励 R(x, τ)，再利用优势函数 A(x, τ) 对路径概率进行加权更新。

从实现角度看，reward 本身不需要可导；真正参与反向传播的是整条路径的对数概率 log π_θ(τ|x)。这意味着：只要能够给出一条路径最终"好不好"的数值评价，就可以用 PPO 更新策略参数，而不要求 reward 对中间跳步变量显式可导。

ΔH_k、H_k 与 F_k 虽然没有单独标签，但它们通过对 h_k 的控制被路径级 reward 间接塑形，从而学会"什么时候更该停"。

## 六、统一训练流程

训练时，离线 demonstrations 只承担"提供起始状态 x 与标注动作 a*"的作用，而不再承担"预先扫描并找出最优 stop time 标签"的作用。

换言之，该方案不是在线真实环境强化学习；它的数据来源是离线 demonstrations，但路径采样与 PPO 更新是基于当前策略的 on-policy 过程。

### 6.1 训练步骤

每一轮训练均对同一个最终模型执行以下流程：

**步骤 1：采样初始状态**

从离线 demonstrations 中采样一批状态 x，作为 chunk 的起始上下文。

**步骤 2：Rollout 路径**

使用当前策略在视频分支中 rollout 一条路径 τ：

```python
初始化：H_0 = 0, k = 0

while k < K_max:
    # 计算 hazard 增量
    ΔH_k = softplus(g(z_k))

    # 累积 hazard
    H_k = H_(k-1) + ΔH_k

    # 计算条件停止概率
    h_k = 1 - exp(-ΔH_k)

    # 采样停止决策
    b_k ~ Bernoulli(h_k)

    if b_k == stop:
        break

    # 采样跳步
    r_k ~ Beta(alpha_k, beta_k)

    # 更新时间
    t_(k+1) = 1 - r_k × (1 - t_k)

    k = k + 1
```

**步骤 3：生成动作**

按路径 τ 完成视频去噪后，进入动作分支，生成机器人动作。

**步骤 4：计算奖励**

```
R(x, τ) = U(x, τ) - λ × Cost(τ)
```

**步骤 5：PPO 更新**

采用 PPO 对路径概率进行更新，使高奖励路径的概率上升，低奖励路径的概率下降。

### 6.2 训练主线

整个训练过程中始终只有这一条主线，不再额外引入 stop-only 子任务。

## 七、工程落地时需要完成的核心改动

### 7.1 视频去噪 loop 改动

在 LingBot-VA 的视频去噪 loop 中加入 scheduler 调用接口，使其在每一步都能够读取 (alpha_k, beta_k, ΔH_k)，并在内部维护 H_k、F_k 与 h_k。

**训练时：**
- 按 Bernoulli/Beta 分布采样动作

**部署时：**
- 输出确定的 stop_now 布尔信号

### 7.2 停止逻辑

保证 stop 发生时，当前步即成为视频 loop 的最后一步，并在该步正确写入 cache，随后再进入动作 loop。

### 7.3 Scheduler Head

新增轻量 scheduler head，输入为 pooled hidden feature、current time 及辅助条件，输出为：
- Beta 参数 (alpha_k, beta_k)
- Hazard 增量 ΔH_k

**建议架构：**

```python
输入：z_k = [hidden_feature, time_embedding, condition]

跳步头：
  alpha_k, beta_k = JumpHead(z_k)

Hazard 头：
  ΔH_k = softplus(HazardHead(z_k))
```

主干 backbone 默认冻结，只更新 scheduler 相关参数。

### 7.4 Reward 计算与 PPO 训练

将 reward 计算逻辑与 PPO 训练逻辑接入现有推理与训练框架，支持对整条路径进行 rollout、记录与更新。

**关键实现：**

```python
def compute_path_log_prob(path, model, x):
    """计算路径的对数概率"""
    log_prob = 0.0
    H = 0.0

    for k, (action, value) in enumerate(path):
        z_k = model.get_state(x, k)

        # 计算 hazard 增量
        delta_H_k = F.softplus(model.hazard_head(z_k))
        H += delta_H_k

        # 计算条件停止概率
        h_k = 1 - torch.exp(-delta_H_k)

        if action == 'stop':
            # 停止的对数概率
            log_prob += torch.log(h_k + 1e-8)
            break
        else:
            # 继续的对数概率
            log_prob += torch.log(1 - h_k + 1e-8)
            # 等价于：log_prob -= delta_H_k

            # 跳步的对数概率
            alpha_k, beta_k = model.jump_head(z_k)
            r_k = value
            log_prob += Beta(alpha_k, beta_k).log_prob(r_k)

    return log_prob
```

### 7.5 部署封装

在部署封装层中显式实现：

```python
def should_stop(k, F_k, K_min=2, K_max=10, eta=0.85):
    """部署期停止判断"""
    if k >= K_max:
        return True
    if k >= K_min and F_k >= eta:
        return True
    return False
```

避免把阈值逻辑硬编码进训练期策略头。

## 八、稳定训练与稳定部署的关键约束

由于该方案从一开始就直接训练最终模型，因此稳定性控制尤为重要。

### 8.1 KL 正则

使用固定 baseline 调度作为 reference policy，并对当前策略加入 KL 正则，避免 hazard 头与 Beta 头在训练初期偏离过快。

```
L_KL = KL(π_θ || π_ref)
```

### 8.2 步数限制

限制最大视频步数 K_max，并对 r_k 的取值范围做合理约束，避免策略在全空间内过度探索。

部署时还建议设置最小允许停止步数 K_min，防止模型在极早阶段就触发停止。

**推荐值：**
```
K_min = 2
K_max = 10
```

### 8.3 参数更新策略

在训练初期只更新 scheduler 参数，不更新共享主干，以减少策略梯度对原始视频—动作表示空间的扰动。

**训练阶段划分：**
```
阶段 1（前 20% 训练）：只更新 hazard_head 和 jump_head
阶段 2（后 80% 训练）：联合更新所有参数
```

### 8.4 Reward 归一化

对 reward 与 advantage 做归一化处理，以降低路径级策略梯度的方差。

```python
advantage = (advantage - mean(advantage)) / (std(advantage) + 1e-8)
```

### 8.5 部署阈值调优

部署阈值 η 不应随意指定，而应在验证集上结合 success-latency frontier 进行 sweep。

**建议搜索范围：**
```
η ∈ {0.70, 0.75, 0.80, 0.85, 0.90}
```

先从这些值开始搜索，绘制 Pareto 曲线，选择最优工作点。

### 8.6 抖动处理

在验证与部署阶段，应将阈值 η 与 reference policy 的平均步数一起联调，而不是孤立设置。

若阈值附近出现抖动，优先采用：
- 较高阈值
- 最小停止步数 K_min
- 双步确认规则

而不是回退到瞬时 stop 概率头。

### 9.1 核心主张

在该统一方案下，论文的核心主张不应再是"找到更好的 stop time"，而应表述为：

**模型能够在视频去噪过程中按状态自适应分配计算预算，同时联合决定"停不停"和"如何跳步"，并直接以最终动作效用减去计算代价作为优化目标。**

## 十、Hazard 方案的数学优势总结

### 10.1 核心公式

```
ΔH_k = softplus(g(z_k))        # Hazard 增量（非负）
H_k = H_(k-1) + ΔH_k            # 累积 Hazard
F_k = 1 - exp(-H_k)             # 累积停止趋势（CDF）
h_k = 1 - exp(-ΔH_k)            # 条件停止概率
```

### 10.2 关键优势

**优势 1：F_0 = 0 天然成立**
```
H_0 = 0  →  F_0 = 1 - exp(0) = 0
```

**优势 2：条件概率直接计算**
```
h_k = 1 - exp(-ΔH_k)
```
不需要差分或除法，只依赖当前增量！

**优势 3：数值稳定**
- 梯度：∂h_k / ∂g(z_k) ∈ (0, 1)，始终有界
- 无除零风险

**优势 4：单调性保证**
```
H_k ≥ H_(k-1)  →  F_k ≥ F_(k-1)
```

**优势 5：PPO 友好**
```
log P(路径在第 τ 步停止) = log(1 - exp(-ΔH_τ)) - H_(τ-1)
```
计算简洁，适合梯度优化。

**优势 6：理论基础扎实**

来自生存分析的标准框架，概率语义严格一致。

### 10.3 数值示例

假设神经网络输出：
```
g(z_1) = 0.5
g(z_2) = 1.0
g(z_3) = 1.5
```

**第 1 步：**
```
ΔH_1 = softplus(0.5) ≈ 1.127
H_1 = 0 + 1.127 = 1.127
F_1 = 1 - exp(-1.127) ≈ 0.676
h_1 = 1 - exp(-1.127) ≈ 0.676
```
意义：第 1 步有 67.6% 的概率停止

**第 2 步：**
```
ΔH_2 = softplus(1.0) ≈ 1.313
H_2 = 1.127 + 1.313 = 2.440
F_2 = 1 - exp(-2.440) ≈ 0.913
h_2 = 1 - exp(-1.313) ≈ 0.731
```
意义：第 2 步有 73.1% 的概率停止

**第 3 步：**
```
ΔH_3 = softplus(1.5) ≈ 1.702
H_3 = 2.440 + 1.702 = 4.142
F_3 = 1 - exp(-4.142) ≈ 0.984
h_3 = 1 - exp(-1.702) ≈ 0.818
```
意义：第 3 步有 81.8% 的概率停止

## 十一、结论

### 11.1 最终建议

只保留一个统一模型和一条统一训练主线。该模型在每一步同时预测：
- Beta 分布参数 (alpha_k, beta_k)
- Hazard 增量 ΔH_k

训练阶段通过策略采样形成整条路径，并以 PPO 直接优化路径概率。

部署阶段再将累计 Hazard 转换为确定的 stop_now 接口，并结合 K_min、K_max 与阈值 η 进行稳定控制。

### 11.2 方案优势

这样可以：
1. 避免在方法定义上来回切换 stop-only 与 stepwise 两套逻辑
2. 获得比瞬时 stop 概率更平滑、更稳定的停止行为
3. 享受 Hazard 建模带来的数值稳定性和理论保证
4. 直接优化路径级目标，符合实际部署需求

### 11.3 实现路线图

- 实现 Hazard Head

## 附录：与原方案的对比

### 原方案（有问题）

```
Δs_k = softplus(g(z_k))
s_k = s_(k-1) + Δs_k
F_k = sigmoid(s_k)
h_k = (F_k - F_(k-1)) / (1 - F_(k-1))  ← 有除法，不稳定
```

**问题：**
- 当 F_(k-1) → 1 时，分母趋近 0，数值不稳定
- 梯度可能爆炸
- F_0 = sigmoid(0) = 0.5，需要解释

### Hazard 方案（推荐）

```
ΔH_k = softplus(g(z_k))
H_k = H_(k-1) + ΔH_k
F_k = 1 - exp(-H_k)
h_k = 1 - exp(-ΔH_k)  ← 无除法，稳定
```

**优势：**
- 数值稳定，无除零风险
- 梯度有界
- F_0 = 0 天然成立
- 理论基础扎实（生存分析）

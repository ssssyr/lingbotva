# LingBot-VA 在 RoboTwin 2.0 上的中文版详细复现指导

本文档面向当前仓库 `/home/syr/code/lingbot-va`，目标是帮助你在 `RoboTwin 2.0` 上尽可能完整地复现论文 **LingBot-VA: Causal World Modeling for Robot Control** 的仿真结果与后训练流程。

我在写这份文档时，已经对照阅读了：

- 论文 `LingBot_VA_paper.pdf`
- 仓库说明 `README.md`
- 训练/推理配置 `wan_va/configs/*.py`
- 推理服务 `wan_va/wan_va_server.py`
- RoboTwin 评测脚本 `evaluation/robotwin/*`
- 数据加载实现 `wan_va/dataset/lerobot_latent_dataset.py`

这份指南不只是“怎么运行”，还会明确指出当前开源版本中和论文之间的对应关系、必须改的占位项、以及真正容易卡住的地方。

## 1. 先说清楚复现范围

### 1.1 这份仓库当前能复现什么

从当前开源代码和 README 看，**最现实的复现目标**有三层：

1. **直接复现 RoboTwin 2.0 推理评测流程**
   - 使用作者发布的 `lingbot-va-posttrain-robotwin` 权重
   - 在 RoboTwin 2.0 中跑 50 个任务
   - 这是最推荐先完成的一步

2. **复现 RoboTwin 2.0 上的 post-training（后训练/微调）**
   - 使用作者发布的 `lingbot-va-base` 基座
   - 使用作者发布的 `robotwin-clean-and-aug-lerobot` 数据集
   - 在本仓库里跑 `wan_va/train.py`
   - 再把你训练出的 `transformer` 接回完整模型目录做推理评测

3. **完全复现论文中的大规模预训练**
   - 论文写到预训练使用了约 `16K hours` 机器人数据、总计 `1.4T tokens`
   - 当前仓库并没有公开完整预训练数据源和完整预训练流水线所需的全部原始数据
   - 因此这部分**原则上无法完整一比一复现**

### 1.2 建议你的实际复现顺序

建议按下面顺序做：

1. 先跑通单任务推理
2. 再跑通 50 任务评测
3. 再做 post-training
4. 最后再尝试调参去逼近论文数值

原因很简单：当前仓库里真正容易出问题的，不是模型本身，而是环境拆分、路径占位符、`attn_mode`、以及训练后检查点和推理目录结构不一致。

## 2. 论文关键信息与代码落点

如果你想“按论文理解项目，再按代码复现”，下面这组映射最重要。

### 2.1 论文方法核心

论文里的 LingBot-VA 是一个统一的视频-动作世界模型，核心点是：

- 用 `Wan2.2-5B` 作为视频流主干
- 在共享时序里交错建模视频 token 和动作 token
- 用 `Mixture-of-Transformers (MoT)` 做双流融合
- 用 `KV Cache` 支持长时序闭环推理
- 用异步执行减少推理阻塞
- 在 RoboTwin 2.0 上做双臂任务评测

### 2.2 当前仓库里的关键实现位置

- 模型主干：`wan_va/modules/model.py`
- 推理服务：`wan_va/wan_va_server.py`
- 训练入口：`wan_va/train.py`
- 数据集读取：`wan_va/dataset/lerobot_latent_dataset.py`
- RoboTwin 评测客户端：`evaluation/robotwin/eval_polict_client_openpi.py`
- RoboTwin 推理配置：`wan_va/configs/va_robotwin_cfg.py`
- RoboTwin 训练配置：`wan_va/configs/va_robotwin_train_cfg.py`

### 2.3 论文里与 RoboTwin 2.0 直接相关的复现实验设定

论文实验部分给出的关键信息如下：

- RoboTwin 2.0 采用多任务训练
- 数据由两部分组成：
  - clean scene：`50 demos / task`
  - heavy randomization：`500 demos / task`
- 共 `50` 个任务
- 视频从原始 `50 Hz` 下采样到 `12.5 Hz`
- 动作频率保持 `50 Hz`
- RoboTwin 上 post-training 学习率为 `1e-5`
- RoboTwin 上后训练步数为 `50K steps`
- 论文表 1 报告均值：
  - `Easy = 92.9%`
  - `Hard = 91.6%`

### 2.4 一个必须知道的“论文设定 vs 开源配置”差异

论文写到：

- 训练时 chunk size `K` 随机采样于 `[1, 4]`
- 部署时使用 `K = 4`
- 视频推理使用 Euler 3 步
- 动作推理使用 Euler 10 步

但当前开源 `RoboTwin` 配置 `wan_va/configs/va_robotwin_cfg.py` 里是：

- `frame_chunk_size = 2`
- `num_inference_steps = 25`
- `action_num_inference_steps = 50`
- `video_exec_step = -1`

这意味着：

- **你想先复现开源结果时，应优先相信当前仓库配置**
- **你想做论文消融或对齐论文推理设定时，再单独改这些参数**

建议不要一开始就强行把开源配置改成论文数字，否则你很难判断问题出在代码、环境还是你自己的改动。

## 3. 环境与硬件建议

## 3.1 推荐硬件

按仓库 README：

- 单卡 RoboTwin 推理，开启 `offload` 时，约需 `24GB VRAM`
- 单卡 `i2va` 推理，约需 `18GB VRAM`

- 跑多任务并行评测：建议 `8 GPU`

### 3.2 强烈建议使用两个独立环境

虽然服务端和客户端必须在**同一台机器**上，但我强烈建议用两个独立环境：

1. `lingbot-va` 环境
   - 跑模型服务端
   - 跑训练

2. `robotwin` 环境
   - 跑 RoboTwin 2.0 仿真客户端

原因是作者本身就是通过 server-client 架构隔离依赖冲突。

### 5.0 先避免最常见的坑

下面所有 RoboTwin 安装操作，都必须在**单独的 `robotwin` 环境**里执行，**不要**在 `lingbot-va` 环境里执行。

如果你在 `lingbot-va` 环境里运行 `bash script/_install.sh`，通常会发生：

- `lingbot-va` 里的 `torch==2.9.0` 被 RoboTwin 依赖改写成 `torch==2.4.1`
- `torchaudio` / `torchvision` 与服务端环境失配
- `pytorch3d` / `curobo` 编译时出现 `nvcc` 版本与 PyTorch CUDA 版本不一致

按你这台机器当前情况，更稳妥的做法是：

```bash
conda create -n robotwin python=3.10.16 -y
conda activate robotwin

export CUDA_HOME=/usr/local/cuda-11.8
export PATH=$CUDA_HOME/bin:$PATH
export LD_LIBRARY_PATH=$CUDA_HOME/lib64:${LD_LIBRARY_PATH:-}

nvcc --version
pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu118
python -c "import torch; print(torch.__version__, torch.version.cuda)"
```

确认这两项都对，再继续执行 RoboTwin 安装：

- `nvcc --version` 显示 `11.8`
- `torch.version.cuda` 显示 `11.8`

## 7. 第四步：先改掉仓库里的占位路径

这是当前仓库里最容易导致“脚本能跑但一定失败”的地方。

### 7.1 修改推理模型路径

编辑 `wan_va/configs/va_robotwin_cfg.py`：

```python
va_robotwin_cfg.wan22_pretrained_model_name_or_path = "/path/to/pretrained/model"
```

改成你的真实模型目录，例如：

```python
va_robotwin_cfg.wan22_pretrained_model_name_or_path = "/data/models/lingbot-va-posttrain-robotwin"
```

### 7.2 修改训练模型路径和数据路径

先说明一件事：

- `va_robotwin_train_cfg.py` 是在 `va_robotwin_cfg.py` 基础上 `update()` 得到的
- 也就是说，`wan22_pretrained_model_name_or_path` 默认是**从 `va_robotwin_cfg.py` 继承过来的**

因此有两种做法：

1. 最简单：直接把 `wan_va/configs/va_robotwin_cfg.py` 里的模型路径改成你的基础模型目录
2. 更清晰：在 `wan_va/configs/va_robotwin_train_cfg.py` 里显式再覆写一次

如果你想把训练和推理模型目录分开，推荐第二种，例如在 `wan_va/configs/va_robotwin_train_cfg.py` 里补上：

```python
va_robotwin_train_cfg.wan22_pretrained_model_name_or_path = "/path/to/models/lingbot-va-base"
va_robotwin_train_cfg.dataset_path = "/path/to/datasets/robotwin-clean-and-aug-lerobot"
```

这里建议：

- `wan22_pretrained_model_name_or_path` 指向 `lingbot-va-base`
- `dataset_path` 指向 `robotwin-clean-and-aug-lerobot`

### 7.3 修改 RoboTwin 根目录

编辑 `evaluation/robotwin/eval_polict_client_openpi.py`：

```python
robowin_root = Path("/path/to/your/robowin")
```

改成你真实的 RoboTwin 目录，例如：

```python
robowin_root = Path("/data/code/RoboTwin")
```

这一步必须改。因为这个脚本会：

- 把 `robowin_root` 插入 `sys.path`
- `os.chdir(robowin_root)`
- 直接导入 `envs`、`task_config`、`description` 等 RoboTwin 模块

### 7.4 如果你不想用 WandB，提前关掉

当前训练配置 `wan_va/configs/va_robotwin_train_cfg.py` 里：

```python
va_robotwin_train_cfg.enable_wandb = True
```

而 `script/run_va_posttrain.sh` 里只是占位：

```bash
export WANDB_API_KEY="your key"
export WANDB_BASE_URL="your url"
export WANDB_TEAM_NAME="your team name"
export WANDB_PROJECT="your project"
```

如果你没有真实 WandB 配置，最简单的做法是：

```python
va_robotwin_train_cfg.enable_wandb = False
```

否则训练很可能一开始就因为 `wandb.login` 报错。

## 8. 第五步：一定要处理 `attn_mode`

这是 README 明确强调的点，也是最常见报错源。

### 8.1 训练和推理的 `attn_mode` 不能混用

需要修改模型目录下：

```text
<your-model-path>/transformer/config.json
```

字段：

```json
"attn_mode": "..."
```

### 8.2 正确规则

- 训练时：`"flex"`
- 推理/评测时：`"torch"` 或 `"flashattn"`

也就是说：

- 训练配置不能拿 `"torch"` 直接跑
- 推理配置不能拿 `"flex"` 直接跑

### 8.3 最推荐的做法

不要在同一个模型目录里反复手改。

建议保留两份目录：

1. `...-train`
   - `transformer/config.json` 里用 `"flex"`

2. `...-infer`
   - `transformer/config.json` 里用 `"flashattn"` 或 `"torch"`

这样最稳。

对应到逻辑上，结果会同时出现在两个地方：

1. `RoboTwin` 原生输出目录 `eval_result/`
2. 你指定的 `${save_root}` 目录

README 已说明：`eval_result/` 是 RoboTwin 自带输出，和结果目录本质重复，可以忽略。

## 10. 复现路径 B：自己做 RoboTwin post-training

这一部分对应论文中“少量任务数据快速适配”的能力，也是当前仓库最值得你自己跑的一部分。

### 10.1 训练前你需要确认的数据格式

当前训练不是直接读取原始视频，而是读取：

1. `LeRobot` 格式元数据与动作
2. 预先提取好的 `Wan2.2 VAE latent`

数据集类 `wan_va/dataset/lerobot_latent_dataset.py` 的要求是：

- 在 `dataset_path` 下递归搜索 `meta/info.json`
- 每个数据集目录下应有 `meta/episodes.jsonl`
- 同时应有对应的 `latents/` 目录
- 根目录还应有 `empty_emb.pt`

### 10.2 作者给出的 RoboTwin 后训练数据

如果你下载的是作者发布的：

- `robbyant/robotwin-clean-and-aug-lerobot`

则它已经是面向当前训练脚本整理好的格式，你不需要自己再把 RoboTwin 原始数据转成 LeRobot。

### 10.3 训练配置建议

编辑 `wan_va/configs/va_robotwin_train_cfg.py`，最少确认这些值：

```python
va_robotwin_train_cfg.wan22_pretrained_model_name_or_path = "/path/to/models/lingbot-va-base"
va_robotwin_train_cfg.dataset_path = "/path/to/datasets/robotwin-clean-and-aug-lerobot"
va_robotwin_train_cfg.empty_emb_path = os.path.join(va_robotwin_train_cfg.dataset_path, 'empty_emb.pt')
va_robotwin_train_cfg.enable_wandb = False
va_robotwin_train_cfg.save_interval = 1000
va_robotwin_train_cfg.batch_size = 1
va_robotwin_train_cfg.gradient_accumulation_steps = 1
va_robotwin_train_cfg.num_steps = 50000
```

说明：

- 论文里 RoboTwin 后训练也是 `50K steps`
- 当前默认 `batch_size=1`
- 如果你 GPU 不多，但又想接近论文建议的全局 batch，可以适当增大 `gradient_accumulation_steps`

### 10.4 开始训练

先确保**训练模型目录**的 `transformer/config.json` 中：

```json
"attn_mode": "flex"
```

然后运行：

```bash
cd /home/syr/code/lingbot-va
NGPU=8 bash script/run_va_posttrain.sh
```

如果你只有单卡或少卡，也可以改成：

```bash
NGPU=1 bash script/run_va_posttrain.sh
```

但训练时间会明显拉长。

### 10.5 训练产物在哪里

默认检查点会保存在：

```text
./train_out/checkpoints/checkpoint_step_xxx/
```

注意一个关键细节：

- 当前 `save_checkpoint()` **只保存 `transformer/`**
- 不会把 `vae/`、`tokenizer/`、`text_encoder/` 一起存下来

这会直接影响你后面怎么做推理评测。

### 10.6 如何把训练产物变成可推理目录

因为推理服务要求完整目录结构，所以你需要把训练得到的 `transformer/` 合并回一个完整模型目录。

最简单做法：

1. 复制一份 `lingbot-va-base`
2. 用你训练出的 `transformer/` 覆盖它

示例：

```bash
cp -r /path/to/models/lingbot-va-base /path/to/models/lingbot-va-robotwin-ft
rsync -a /home/syr/code/lingbot-va/train_out/checkpoints/checkpoint_step_50000/transformer/ /path/to/models/lingbot-va-robotwin-ft/transformer/
```

然后把新的推理目录：

```text
/path/to/models/lingbot-va-robotwin-ft
```

写回 `wan_va/configs/va_robotwin_cfg.py` 的：

```python
va_robotwin_cfg.wan22_pretrained_model_name_or_path = "..."
```

最后别忘了把这个新目录里的 `transformer/config.json` 改成推理模式：

```json
"attn_mode": "flashattn"
```

或：

```json
"attn_mode": "torch"
```

1. 改推理配置路径
2. 启动服务端

## 11. 如果你想用自己的数据做 post-training

README 已经给了数据规范，结合代码可以总结为下面这套最关键约束。

### 11.1 必须先转成 LeRobot 格式

也就是要有：

- `meta/`
- `videos/`
- `episodes.jsonl`

### 11.2 `episodes.jsonl` 里必须补 `action_config`

每个 episode 至少要有：

```json
{
  "episode_index": 0,
  "tasks": ["task description"],
  "length": 450,
  "action_config": [
    {
      "start_frame": 0,
      "end_frame": 450,
      "action_text": "Natural language description of the robot action in this segment."
    }
  ]
}
```

### 11.3 必须提前抽取视频 latent

当前训练不会在线编码原视频，而是直接读 `.pth` latent 文件。

目录结构需要像这样：

```text
your_dataset/
├── videos/
│   └── chunk-000/
│       └── observation.images.cam_high/
├── latents/
│   └── chunk-000/
│       └── observation.images.cam_high/
│           └── episode_000000_0_450.pth
└── meta/
    └── episodes.jsonl
```

### 11.4 latent 文件命名必须匹配

命名格式必须是：

```text
episode_{episode_index}_{start_frame}_{end_frame}.pth
```

并和 `action_config` 的区间严格对应。

### 11.5 当前模型使用的统一动作空间

论文和代码都采用 30 维统一动作接口：

- 左臂 EEF pose：7 维
- 右臂 EEF pose：7 维
- 左臂 joints：7 维
- 右臂 joints：7 维
- 左夹爪：1 维
- 右夹爪：1 维

总计：

```text
(7 + 7 + 1) * 2 = 30
```

如果你的机器人动作维度不一致，需要在数据加载时映射到这个 30 维空间，不存在的维度补 0。

## 12. 当前 RoboTwin 评测脚本里几个容易让人误解的点

### 12.1 `policy_name=ACT` 不代表你在跑 ACT

`evaluation/robotwin/launch_client.sh` 和 `launch_client_multigpus.sh` 里默认：

```bash
policy_name=ACT
```

但这个评测脚本最终真正调用的是：

```python
model = WebsocketClientPolicy(port=usr_args['port'])
```

也就是说：

- 真正产生动作的是 LingBot-VA 的 websocket 服务端
- `ACT` 更多只是沿用 RoboTwin 侧的配置命名和路径结构

不要被这个变量名误导。

### 12.2 评测脚本默认假设相机键名固定

`format_obs()` 写死了三路观测：

- `observation.images.cam_high`
- `observation.images.cam_left_wrist`
- `observation.images.cam_right_wrist`

这和 `va_robotwin_cfg.py` 的 `obs_cam_keys` 必须保持一致。

### 12.3 评测假设动作频率是视觉频率的 4 倍

客户端里有：

```python
assert action.shape[2] % 4 == 0
```

这对应论文里的：

- 视频 `12.5Hz`
- 动作 `50Hz`

也就是每个视觉关键帧对应 4 个动作时间步。不要随便改掉这个时序关系。

## 13. 常见失败点排查清单

### 13.1 服务端起不来

优先检查：

- 模型目录是否完整包含 `vae/tokenizer/text_encoder/transformer`
- `attn_mode` 是否为推理模式
- `flash-attn` 是否安装成功
- GPU 显存是否足够

### 13.2 客户端一直等待 websocket

优先检查：

- 服务端端口和客户端端口是否一致
- 单卡时应匹配 `29056`
- 多卡时应匹配 `29556 + GPU offset`
- 服务端和客户端是否在同一台机器

### 13.3 训练刚开始就报 WandB 错

处理方法二选一：

1. 提供真实 WandB 环境变量
2. 把 `enable_wandb=False`

### 13.4 训练能跑，推理时报目录缺失

这是因为训练只保存了 `transformer/`，你还没有把它合并回完整推理目录。

### 13.5 推理时报注意力模式错误

检查：

```text
<model>/transformer/config.json
```

是不是：

- 训练：`flex`
- 推理：`torch` 或 `flashattn`

### 13.6 结果明显低于论文

优先排查以下一致性：

1. RoboTwin 提交版本是否一致
2. 权重是否真的是 `posttrain-robotwin`
3. 评测是否用了相同任务组和次数
4. 是否无意中改了 `frame_chunk_size`、guidance、推理步数
5. 是否混用了训练和推理模型目录

## 15. 总结

如果你的目标是“在 RoboTwin 2.0 上把这篇论文复现出来”，最关键的不是再去补很多额外代码，而是先把下面四件事做对：

1. **环境分离**：LingBot-VA 和 RoboTwin 用两套环境
2. **路径改对**：模型路径、数据路径、`robowin_root`
3. **`attn_mode` 切对**：训练用 `flex`，推理用 `torch/flashattn`
4. **目录结构对**：推理必须是完整模型目录，训练保存的 `transformer/` 不能直接拿来推理

只要这四件事对齐，当前仓库已经具备在 RoboTwin 2.0 上复现 LingBot-VA 推理和后训练流程的基本条件。

# LingBot-VA 使用作者权重直接复现 RoboTwin 2.0 推理评测详细指南

本文档只聚焦一件事：

- **不做训练**
- **直接使用作者发布的 `lingbot-va-posttrain-robotwin` 权重**
- **在 RoboTwin 2.0 上跑通推理评测**

如果你的目标是先把论文里的第一步复现出来，这份文档就是你现在该照着走的版本。

---

## 1. 复现目标与成功标准

你现在要复现的是：

- 使用作者发布的后训练权重
- 启动 LingBot-VA 服务端
- 让 RoboTwin 2.0 客户端通过 websocket 请求动作
- 完成单任务冒烟测试
- 然后完成 50 任务评测
- 最后统计成功率

你可以把“复现成功”分成三个层级：

### Level 1：单任务跑通

做到这些就算第一关通过：

- 服务端正常启动
- 客户端能连上服务端
- 一个任务完整跑完
- 结果目录里有可视化视频和指标文件

### Level 2：多任务评测跑通

做到这些就算第二关通过：

- 能批量跑多组任务
- 各任务都能输出视频与成功率
- `calc_stat.py` 能正常汇总

### Level 3：结果逼近论文

论文表 1 给出的 RoboTwin 2.0 平均结果是：

- `Easy ≈ 92.9%`
- `Hard ≈ 91.6%`

如果你使用作者原始发布权重，并且环境、RoboTwin 版本、评测方式都对齐，最终结果应该接近这个量级。

## 3. 你至少需要准备好的东西

## 3.1 软件环境

你需要两套环境，建议分开：

### 环境 A：`lingbot-va`

负责：

- 启动 LingBot-VA 服务端
- 加载模型权重

如果你只是先做单任务验证：

- `1 x 24GB` GPU 基本够用

如果你想尽快完成 50 任务批量评测：

- `8 GPU` 最理想

## 5. 第二步：准备 RoboTwin 2.0 环境

这里按当前仓库 `README.md` 提供的做法走。

### 5.0 先说最重要的一句

下面所有 RoboTwin 安装命令，都必须在**单独的 `robotwin` 环境**里执行，**不要**在 `lingbot-va` 环境里执行。

否则很容易发生两类问题：

- 把 `lingbot-va` 里的 `torch==2.9.0` 替换成 RoboTwin 需要的 `torch==2.4.1`
- 在编译 `pytorch3d` / `curobo` 时出现 `nvcc` 和 PyTorch CUDA 版本不一致

按你这台机器当前情况，建议直接这样做：

```bash
conda create -n robotwin python=3.10.16 -y
conda activate robotwin

export CUDA_HOME=/usr/local/cuda-11.8
export PATH=$CUDA_HOME/bin:$PATH
export LD_LIBRARY_PATH=$CUDA_HOME/lib64:${LD_LIBRARY_PATH:-}

nvcc --version
pip install torch==2.4.1 torchvision==0.19.1 --index-url https://download.pytorch.org/whl/cu118
python -c "import torch; print(torch.__version__, torch.version.cuda)"
```

你应该至少确认：

- `nvcc --version` 显示 `11.8`
- `python -c "import torch; print(torch.version.cuda)"` 显示 `11.8`

这个目录必须至少包含：

```text
/path/to/models/lingbot-va-posttrain-robotwin/

├── tokenizer/
```

这一步必须确认。因为服务端 `wan_va/wan_va_server.py` 会直接从这个完整目录里加载：

- `vae`
- `tokenizer`
- `text_encoder`
- `transformer`

如果你手里只有一个单独的 `transformer/`，那不是当前这一步要用的目录。

## 7. 第四步：改掉当前仓库里的三个关键占位项

这是当前最容易忽略、但不改就一定跑不通的部分。

## 7.1 改模型路径

编辑文件：

- `wan_va/configs/va_robotwin_cfg.py`

把：

```python
va_robotwin_cfg.wan22_pretrained_model_name_or_path = "/path/to/pretrained/model"
```

改成你的真实路径，例如：

```python
va_robotwin_cfg.wan22_pretrained_model_name_or_path = "/data/models/lingbot-va-posttrain-robotwin"
```

## 7.2 改 RoboTwin 根目录

编辑文件：

- `evaluation/robotwin/eval_polict_client_openpi.py`

把：

```python
robowin_root = Path("/path/to/your/robowin")
```

改成你的真实 RoboTwin 根目录，例如：

```python
robowin_root = Path("/data/code/RoboTwin")
```

这个路径必须对。因为这个脚本启动时会：

1. 把 `robowin_root` 加进 `sys.path`
2. `os.chdir(robowin_root)`
3. 从 RoboTwin 目录里导入：
   - `envs`
   - `task_config`
   - `description`
   - `policy/.../deploy_policy.yml`

也就是说，这一步其实决定了客户端到底能不能把 RoboTwin 跑起来。

## 7.3 改推理用 `attn_mode`

编辑：

```text
/path/to/models/lingbot-va-posttrain-robotwin/transformer/config.json
```

确保：

```json
"attn_mode": "flashattn"
```

如果你没装好 `flash-attn`，那就改成：

```json
"attn_mode": "torch"
```

注意：

- 推理评测时**不能**是 `"flex"`
- `"flex"` 只适合训练

## 8. 第五步：先做单任务冒烟测试

不要一上来就跑 50 个任务。先验证一条链路完整打通。

## 8.1 先启动服务端

在 `lingbot-va` 环境中：

```bash
conda activate lingbot-va
cd /home/syr/code/lingbot-va
bash evaluation/robotwin/launch_server.sh
```

这个脚本实际会做的事情是：

- 用 `config-name robotwin` 启动 `wan_va/wan_va_server.py`
- 启动单个服务实例
- 端口默认是 `29056`
- 服务端保存目录默认是 `visualization/`

脚本内容对应的是：

```bash
START_PORT=${START_PORT:-29056}
MASTER_PORT=${MASTER_PORT:-29061}
...
python -m torch.distributed.run \
    --nproc_per_node 1 \
    --master_port $MASTER_PORT \
    wan_va/wan_va_server.py \
    --config-name robotwin \
    --port $START_PORT \
    --save_root $save_root
```

### 你应该看到什么

正常情况下，服务端会：

- 成功加载模型
- 进入 websocket server 模式
- 等待客户端连接

如果这里起不来，先不要继续客户端。

## 8.2 再启动单任务客户端

在 `robotwin` 环境中，另开一个终端：

```bash
conda activate robotwin
cd /home/syr/code/lingbot-va
task_name="adjust_bottle"
save_root="results/"
bash evaluation/robotwin/launch_client.sh ${save_root} ${task_name}
```

如果你不想每次手敲参数，也可以直接改：

- `evaluation/config/robotwin_client.yaml`

然后直接运行：

```bash
bash evaluation/robotwin/launch_client.sh
```

或者显式指定配置文件：

```bash
bash evaluation/robotwin/launch_client.sh --config evaluation/config/robotwin_client.yaml
```

这个脚本默认会：

- 调用 `evaluation.robotwin.eval_polict_client_openpi`
- 任务配置使用 `task_config=demo_clean`
- 评测次数 `test_num=100`
- 连接端口 `29056`

也就是它默认和上面的单卡服务端端口完全一致。

## 8.3 客户端实际在做什么

这个评测客户端的关键流程是：

1. 用 RoboTwin 环境创建任务
2. 调用 `TASK_ENV.get_instruction()` 生成语言指令
3. 给服务端发送一次 `reset=True`
4. 发送第一帧观测，拿回一个动作 chunk
5. 在仿真里执行动作
6. 每过一个视觉关键帧，把新观测回传给服务端更新 KV cache
7. 重复直到成功或超步数

服务端接口在 `wan_va/wan_va_server.py` 里对应三类请求：

- `reset=True`
- `compute_kv_cache=True`
- 普通 `obs=...` 推理请求

所以只要客户端和服务端连上了，整条闭环控制链就真的在跑了。

## 8.4 单任务跑通后结果在哪

有一个非常容易误解的点：

- `eval_polict_client_openpi.py` 启动后会 `os.chdir(robowin_root)`

所以结果里的相对路径其实是**相对于 RoboTwin 根目录**。

也就是说，如果你传的是：

```bash
save_root="results/"
```

那么最终结果通常会写到：

```text
<RoboTwin 根目录>/results/
<RoboTwin 根目录>/eval_result/
```

其中：

- `results/` 是你传入的保存目录
- `eval_result/` 是 RoboTwin 原生输出目录

两边内容会有重复，README 也说明了 `eval_result/` 可以忽略。

单任务跑完后，你通常会看到：

- 可视化视频
- 成功/失败标记
- 指标 `res.json`

## 9. 单任务之后，先做一次结果检查

在继续大规模评测之前，建议你人工检查下面几件事。

## 9.1 服务端是否真的被调用了

你应该能在服务端终端里看到类似：

- reset
- infer one chunk
- compute kv cache

这样的日志节奏。

如果客户端跑了，但服务端没任何日志，通常是：

- 端口不对
- 客户端没连上

## 9.2 任务结果目录是否正常生成

重点看下面两个目录有没有内容：

```text
<RoboTwin 根目录>/results/
<RoboTwin 根目录>/eval_result/
```

## 9.3 输出动作是否正常

客户端执行动作时，如果服务端返回内容异常，通常会表现为：

- 一直等待
- 动作维度不匹配
- 仿真里立刻异常失败

当前脚本假定：

- 三路图像输入固定
- 双臂动作格式固定
- 视觉频率和动作频率的关系固定

所以如果这里出错，通常不是算法问题，而是环境或路径问题。

## 10. 第六步：开始跑 50 任务评测

如果单任务通过了，再开始完整评测。

## 10.1 多卡服务端启动方式

在 `lingbot-va` 环境中：

```bash
conda activate lingbot-va
cd /home/syr/code/lingbot-va
bash evaluation/robotwin/launch_server_multigpus.sh
```

这个脚本会：

- 使用 8 张卡
- 每张卡起一个服务实例
- 端口从 `29556` 开始递增
- 每个实例日志保存在 `./logs/`

对应关系是：

- GPU 0 -> port `29556`
- GPU 1 -> port `29557`
- GPU 2 -> port `29558`
- ...
- GPU 7 -> port `29563`

### 注意

这个脚本内部用了 `nohup ... &`，但最后还有 `wait`，所以：

- 服务会在后台跑
- 启动脚本所在终端也会一直挂着

这是正常现象。不要手动把它关掉。

## 10.2 多任务客户端启动方式

在 `robotwin` 环境中：

```bash
conda activate robotwin
cd /home/syr/code/lingbot-va
save_root="results/"
task_group_id=0
bash evaluation/robotwin/launch_client_multigpus.sh ${save_root} ${task_group_id}
```

这个脚本会：

- 从 7 个任务组里选一个组
- 每组 8 个任务
- 每个任务自动连接对应端口
- 后台并发运行
- 把每个任务日志写到 `./logs/`

### `task_group_id` 范围

可选值：

- `0`
- `1`
- `2`
- `3`
- `4`
- `5`
- `6`

### 为什么是 7 组

因为：

- 真实任务一共 50 个
- 作者为了适配 8 卡并行，把任务补到 56 个槽位
- 再切成 7 组，每组 8 个
- 最后一组包含重复任务，只是为了凑满

所以你做完整评测时，最好逐组运行：

```bash
task_group_id=0
task_group_id=1
task_group_id=2
task_group_id=3
task_group_id=4
task_group_id=5
task_group_id=6
```

## 13. 常见报错与最直接的处理方式

## 13.1 服务端启动就报模型加载失败

优先检查：

1. 模型目录是不是完整目录，不是单独 `transformer/`
2. `wan22_pretrained_model_name_or_path` 是否写对
3. `attn_mode` 是否适合推理
4. 显存是否足够

## 13.2 客户端一直显示等待连接

优先检查：

1. 服务端是否真的启动成功
2. 单卡时端口是不是 `29056`
3. 多卡时端口是不是 `29556 + 偏移`
4. 服务端和客户端是不是在同一台机器

## 13.3 客户端报找不到 `envs` 或 `task_config`

基本就是：

- `robowin_root` 没改
- 或者改错了

## 13.4 客户端报找不到 `policy/ACT/deploy_policy.yml`

这通常说明：

- RoboTwin 环境没有安装完整
- 或 RoboTwin 当前目录结构和脚本假定不一致

因为评测脚本在 `os.chdir(robowin_root)` 后，是按 RoboTwin 根目录下的相对路径去找这个文件的。

## 13.5 推理时报 attention mode 错误

检查：

```text
<模型目录>/transformer/config.json
```

是不是：

- `"flashattn"` 或 `"torch"`

不是：

- `"flex"`

## 13.6 结果明显低于论文

优先核对：

1. RoboTwin 是否固定在 `2eeec322`
2. 用的是不是 `lingbot-va-posttrain-robotwin`
3. 有没有改过 `guidance_scale`
4. 有没有改过推理步数
5. 是否真的完成了 50 任务评测，而不是只跑了部分组

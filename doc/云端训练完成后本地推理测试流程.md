# 云端训练完成后本地推理测试流程

本文档给出一套可复用流程：

1. 云端训练完成后，把 `checkpoint_step_xxx/transformer` 拉回本地
2. 在本地组装成**完整可推理模型目录**
3. 用现有 RoboTwin 评测脚本做推理测试

适用于当前仓库的 LingBot-VA RoboTwin 流程。

---

## 1. 一个关键前提

训练保存的 checkpoint **默认只有 `transformer/`**，不包含：

- `vae/`
- `tokenizer/`
- `text_encoder/`

但推理服务要求 `wan22_pretrained_model_name_or_path` 指向一个**完整模型目录**。也就是说，训练好的 `checkpoint_step_50000/transformer` 不能直接当作完整推理目录使用。

你需要把训练得到的 `transformer/` 合并回一个完整模型骨架里。

---

## 2. 当前推荐做法

本仓库已经提供了两个脚本：

- [script/cfff-fetch.sh](/home/syr/code/lingbot-va/script/cfff-fetch.sh)
  从远端 CFFF DSW 实例拉取文件或目录到本地
- [script/assemble_robotwin_infer_model.sh](/home/syr/code/lingbot-va/script/assemble_robotwin_infer_model.sh)
  用完整模型骨架 + 新 checkpoint transformer 组装本地可推理目录

## 3. 远端训练完成后，先把 transformer 拉回本地

假设远端训练输出目录是：

```text
train_out/robotwin_author_1gpu_wandb_s10k
```

假设你要拉取第 `50000` 步 checkpoint：

```bash
cd /home/syr/code/lingbot-va

./script/cfff-fetch.sh \
  train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer/ \
  train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer/
```

这条命令会把远端的：

```text
train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer/
```

同步到本地同路径。

你可以先检查一下：

```bash
find train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer -maxdepth 2 -type f | sort
du -sh train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer
```

## 4. 在本地组装成完整可推理目录

### 4.1 推荐使用的完整模型骨架

你本机当前已经有作者完整模型目录：

```text
/mnt/sda/syr/models/lingbot-va-posttrain-robotwin
```

它包含：

- `vae/`
- `tokenizer/`
- `text_encoder/`
- `transformer/`

这类完整目录可以直接作为骨架使用。

### 4.2 组装命令

```bash
cd /home/syr/code/lingbot-va

./script/assemble_robotwin_infer_model.sh \
  --base-model /mnt/sda/syr/models/lingbot-va-posttrain-robotwin \
  --transformer-dir train_out/robotwin_author_1gpu_wandb_s10k/checkpoints/checkpoint_step_50000/transformer \
  --output-dir train_out/robotwin_author_1gpu_wandb_s10k/infer_model_step_50000 \
  --attn-mode torch
```

执行后你会得到：

```text
train_out/robotwin_author_1gpu_wandb_s10k/infer_model_step_50000
```

它应包含：

- `vae/`
- `tokenizer/`
- `text_encoder/`
- `transformer/`
- `configuration.json`
- `README.md`

注意：

- 脚本会把 `transformer/config.json` 里的 `attn_mode` 自动改成推理模式
- 推荐先用 `torch`
- 如果本地 `flash-attn` 环境稳定，可以改成 `flashattn`

你可以核对：

```bash
find train_out/robotwin_author_1gpu_wandb_s10k/infer_model_step_50000 -maxdepth 2 \( -type d -o -type f \) | sort
```

## 5. 如何在本地运行这个 checkpoint 的推理测试

### 5.1 服务端

在 `lingbot-va` 环境里启动：

```bash
conda activate lingbot-va
cd /home/syr/code/lingbot-va

export LINGBOT_VA_MODEL_PATH=/home/syr/code/lingbot-va/train_out/robotwin_author_1gpu_wandb_s10k/infer_model_step_50000

bash evaluation/robotwin/launch_server.sh --config evaluation/config/robotwin_client.yaml
```

这里最关键的是：

```bash
export LINGBOT_VA_MODEL_PATH=...
```

因为 [wan_va/configs/va_robotwin_cfg.py](/home/syr/code/lingbot-va/wan_va/configs/va_robotwin_cfg.py) 会优先读这个环境变量。

### 5.2 客户端

在 `robotwin` 环境里另开终端：

```bash
conda activate robotwin
cd /home/syr/code/lingbot-va

bash evaluation/robotwin/launch_client.sh --config evaluation/config/robotwin_client.yaml
```

### 5.3 单任务测试示例

如果你只想先做一个单任务冒烟：

```bash
conda activate robotwin
cd /home/syr/code/lingbot-va

save_root="results/checkpoint_step_50000_smoke"
task_name="adjust_bottle"

bash evaluation/robotwin/launch_client.sh "${save_root}" "${task_name}" 0 5
```

含义是：

- 保存到 `results/checkpoint_step_50000_smoke`
- 任务是 `adjust_bottle`
- `render_freq=0`
- `test_num=5`

### 5.4 多任务评测

如果你已经把 `evaluation/config/robotwin_client.yaml` 配好，也可以直接：

```bash
conda activate robotwin
cd /home/syr/code/lingbot-va

bash evaluation/robotwin/launch_client.sh --config evaluation/config/robotwin_client.yaml
```

## 7. 常见坑

### 7.1 为什么训练好的 checkpoint 不能直接拿来推理

因为训练保存的是：

```text
.../checkpoint_step_xxx/transformer/
```

而服务端会从模型目录下读取：

- `vae/`
- `tokenizer/`
- `text_encoder/`
- `transformer/`

只给它一个 `transformer/` 子目录是不够的。

### 7.2 为什么 `text_encoder` 里会有 3 个模型文件

不是 3 个不同模型，而是一个大模型被拆成 3 个分片：

- `model-00001-of-00003.safetensors`
- `model-00002-of-00003.safetensors`
- `model-00003-of-00003.safetensors`

这是 Hugging Face 常见的分片保存方式，必须连同：

```text
model.safetensors.index.json
```

一起保留。

### 7.3 为什么要改 `attn_mode`

训练 checkpoint 往往还是：

```json
"attn_mode": "flex"
```

这适合训练，不适合评测。

推理时必须改成：

- `"torch"`
或
- `"flashattn"`

脚本 `assemble_robotwin_infer_model.sh` 已经自动做了这一步。

---

## 8. 以后推荐固定流程

以后每次云端训练结束后，建议固定使用下面三步：

1. `./script/cfff-fetch.sh ...checkpoint_step_xxx/transformer ...`
2. `./script/assemble_robotwin_infer_model.sh ...`
3. `export LINGBOT_VA_MODEL_PATH=... && bash evaluation/robotwin/launch_server.sh`

这样就不会再手动漏掉：

- `vae/`
- `tokenizer/`
- `text_encoder/`
- `attn_mode`

这些最容易出错的环节。
